Execution order

  1. Phase 1 — Registry: CloudBro + role column into fleet-hosts.conf.
  2. Phase 2 — SSH config cleanup (Mac): one block per host, single IdentityFile, kill grab-bag + duplicates.
  3. Phase 5 — Tailscale SSH recovery first: RunSSH on servers, check mode from member devices — the break-glass layer goes live before any door closes.
  4. Phase 3 — Key migration + SuperBro lockout: new keys verified over tailnet, then public :22 closed (D3).
  5. Phase 4 — ACLs: matrix above applied incrementally with policy tests + probe verification.
  6. Phase 6 — Dashboard: script probes every ordered pair (tailscale ping + TCP), regenerates this graph with live latency/state.

Step-by-step guide (follow along during execution)

Run phases in order. Each phase ends with a verification step — do not proceed until it passes. A pilot session (Pi agent) can execute each phase; show it this section.

Phase 1 — Registry

  1. Add to config/fleet-hosts.conf: cloudbro|100.100.1.11|27789|christian|cloudbro|allowed|ssh|Orchestrator devbox
  2. Add role to each line: pilot (mac, monsterbro-win), workstation (monsterbro-wsl), server (linuxbro, superbro), orchestrator (cloudbro).
  3. Update scripts/install/ssh-superbro.sh parsing for the new column.
  4. Verify: ./stow.sh plan macos clean; re-run ssh-superbro.sh idempotently (no diff).

Phase 2 — SSH config cleanup (Mac)

  1. In scripts/install/ssh-superbro.sh: each destination gets exactly one block — Tailscale IP, port 27789, one explicit IdentityFile (temporarily the current working key per host).
  2. Delete the Host * IdentityFile grab-bag and all duplicate blocks (superbro public variant, dup monsterbro/linuxbro).
  3. Verify: ssh -o BatchMode=yes superbro true, same for linuxbro, monsterbro, cloudbro, higgins-writer; ssh -v shows exactly one key offered per host.

Phase 5 — Tailscale SSH recovery (before any lockout)

  1. On each server (linuxbro, superbro, cloudbro): sudo tailscale up --ssh (or enable SSH in admin console).
  2. Admin console → policy: add SSH rule autogroup:member → tag:server + tag:orchestrator, action check, users autogroup:nonroot, root.
  3. Verify (break-glass test): from Mac tailscale ssh christian@superbro true; from iPhone/iPad Tailscale app SSH into one server; confirm it prompts re-auth per check period.

Phase 3 — Key migration + SuperBro lockout

  1. On Mac: ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_mac and ssh-keygen -t ed25519 -f ~/.ssh/agent_mac_ed25519. Repeat on monsterbro-wsl, linuxbro, superbro with their names. CloudBro: agent key only.
  2. Append each public key to target servers' ~/.ssh/authorized_keys with restriction: from="100.100.1.20" ssh-ed25519 AAAA... mac (pin source tailnet IP; agent keys under a marked # agent keys section; create agent@ user per D7 where automation runs).
  3. Verify each new key over tailnet before removing anything: ssh -i ~/.ssh/id_ed25519_mac superbro true.
  4. Only then: close SuperBro public :22 (Contabo firewall / sshd ListenAddress on tailnet IP or AddressFamily rules), remove the public-IP block from ~/.ssh/config.
  5. Remove legacy lines from all servers' authorized_keys (incl. the github key on SuperBro). Delete orphaned local private keys after verifying all servers reject them.
  6. Verify: old keys fail (ssh -i ~/.ssh/github superbro-ts → permission denied), new keys pass, Tailscale SSH still works as backstop.

Phase 4 — ACLs

  1. Draft the policy file per the ACL matrix above; include tests asserting allow/deny pairs.
  2. Apply incrementally in admin console: pilots→servers first; probe; then pilots→cloudbro; probe; then orchestrator grants; probe; finally server→anything deny; probe.
  3. After each step re-run fleet probes (fleet-update or manual tailscale ping + TCP checks) — automation must stay green.
  4. Verify: tailscale status + dashboard graph matches the matrix; Paseo-over-SSH, fleet-update, dockhand all still work.

Phase 6 — Dashboard

  1. Script reads fleet-hosts.conf; per ordered pair runs tailscale ping (direct/relayed, latency) + TCP connect to :27789.
  2. Regenerates this HTML's graph section with live state (green/red arrows, latency labels).
  3. Verify: graph matches ACL matrix; run after every future ACL change.
Rollback per phase: dotfiles → git revert; SSH keys → keep old keys until phase N+1 verified; ACLs → re-edit policy in admin console; SuperBro :22 → reopen firewall rule. Tailscale SSH (Phase 5) is the permanent safety net for all later phases.
