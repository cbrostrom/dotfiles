Add aria2/AriaNg to the downloaders stack, behind gluetun.

Run hurlenko/aria2-ariang inside the existing downloaders project, sharing gluetun’s network namespace so all BT/HTTP traffic exits the NordVPN tunnel. UI on LAN, tailnet, and Traefik at dl.superbro.dk.

Gluetun v3.41.3 (NordVPN, Sweden)network_mode: service:gluetunLAN + tailnet portsTraefik internal-only
This HTML runs no server commands. Copy buttons give text. All traffic from aria2 rides gluetun; if gluetun’s healthcheck fails, aria2 is unreachable and downloads pause. Recreating gluetun restarts every downloader (qbit, sabnzbd, slskd, metube) in the stack; active connections re-establish on their own.

Step 02

Generate once, keep private
openssl rand -base64 24

Store the value only as a Dockhand stack variable (step 3). The RPC secret gates the aria2 JSON-RPC interface; without it anyone who can reach port 8980 can control aria2, including downloading into any mapped directory.

Checkpoint: one random secret in your clipboard/ssh session, not pasted into chat or git.

Step 03

This stack keeps secrets in Dockhand’s built-in stack variables, not in .env files. Dockhand injects them into the container environment at deploy time.

  1. Open Dockhand (docker-lab.superbro.dk) → stacks → downloaders.
  2. Open the stack’s variables / stack variables editor (not the compose YAML, not the env file).
  3. Add one variable:
New stack variable — value is your generated secret
ARIA2_RPC_SECRET=paste-the-generated-secret-here

Save. Dockhand redeploys picks it up; the compose file still only references ${ARIA2_RPC_SECRET}, so nothing secret is ever committed to the mirror.

Checkpoint: variable saved in Dockhand; value exists in no file, no chat history and no git repo.

Step 04

Docker creates missing bind-mount source dirs as root-only when a container starts, which produces confusing permission errors. Create them explicitly with your normal UID/GID 1000, matching the rest of the stack.

Edit C — new aria2 service

Add as a new top-level service next to metube
  aria2:
    image: hurlenko/aria2-ariang:latest
    container_name: aria2
    network_mode: "service:gluetun"
    restart: unless-stopped
    depends_on:
      gluetun:
        condition: service_healthy
    environment:
      - RPC_SECRET=${ARIA2_RPC_SECRET}
      - UPDATE_TRACKERS=yes
    volumes:
      - /home/christian/.config/appdata/aria2:/aria2/conf
      - /media/4tb/Downloads/aria2:/aria2/data
    mem_limit: 512m
    cpus: 0.50
Use the real values from step 1 for both volume sources — the snippet placeholders must be replaced if DOCKER_VOLUME_CONFIG or CLOUDBRO_VOLUME_MEDIA differ. Do not give the aria2 service a networks: or ports: key: it inherits gluetun’s netns, and composing both fails validation.

Step 06

The repo-sync container on linuxbro runs hourly: it pulls master, detects that linuxbro/downloaders/ changed, and redeploys exactly that stack (docker compose up -d --remove-orphans). The RPC secret is a Dockhand stack variable (step 3), injected at deploy time regardless of what triggers the deploy.

On the Mac clone
cd ~/.config/superbro-compose
git pull --rebase
git add linuxbro/downloaders/docker-compose.yml
git commit -m "linuxbro/downloaders: add aria2-ariang behind gluetun (dl.superbro.dk)"
git push origin master
# then watch what repo-sync does on linuxbro:
ssh linuxbro 'docker logs -f --tail 10 repo-sync'   # ctrl-c to stop watching
Do not race repo-sync. The cycle is ≤ 60 min; a host-side docker compose up or a premature Dockhand UI Deploy can conflict with the hourly pull. Only if repo-sync reports a conflict or error, fall back to a manual Dockhand UI deploy of the corrected file.

Checkpoint: push accepted; repo-sync log shows pull + a deploy of downloaders without conflict.

Step 07

Recreating gluetun restarts the other members of the project; that is expected. Verify through SSH on linuxbro:

Verify the recreated stack and the RPC
docker inspect gluetun --format '{{.State.Health.Status}}'
docker logs --tail 40 aria2
docker inspect aria2 --format 'Status: {{.State.Status}}'

aria2 logs should show aria2 RPC listening on port 6800 and the AriaNg web server on 8080. If gluetun logs repeat blocked-inbound warnings for 8980, gluetun’s firewall needs the port allowed; check its actual log line before changing anything.

Checkpoint: gluetun healthy again, aria2 running, RPC line in logs.

Step 08

  • □ From a LAN device: http://192.168.1.100:8980 opens AriaNg.
  • □ From a non-LAN tailnet device: http://100.100.1.100:8980 opens AriaNg.
  • □ http://dl.superbro.dk opens AriaNg from both, and is refused (403/timeouts) from public networks.
  • □ AriaNg connects to the RPC with your secret (it prompts; check “referencing” shows connected).
  • □ Drop a small HTTP file or magnet via AriaNg and see the download land in /media/4tb/Downloads/aria2.
  • □ Confirm aria2’s own exit IP inside gluetun (container log or docker exec aria2 sh -c 'nc -w3 ifconfig.me 80'; echo); if inconclusive, gluetun’s log shows the NordVPN handshake carrying traffic for the whole netns.

Negative tests done with care: RPC without the secret must fail (HTTP 401/403 from AriaNg log or aria2 RPC error), and traefik access to dl.superbro.dk from a non-whitelisted IP must not serve content.

Checkpoint: all boxes above ticked before considering the install done.

Step 10

Primary rollback is a git revert — repo-sync then redeploys the pre-change state within the cycle:

Revert on the Mac clone; repo-sync deploys the restored file
cd ~/.config/superbro-compose
git revert <commit-from-step-6>
git push origin master
ssh linuxbro 'docker logs -f --tail 10 repo-sync'

Emergency-only alternative (if the repo is broken): the host backup prepared in step 1, restored on linuxbro with docker compose --project-directory . -f docker-compose.yml.pre-aria2 --env-file .env up -d — the stack variable is not injected there, which does not matter in rollback since the aria2 service no longer exists in that file. Delete the ARIA2_RPC_SECRET stack variable in Dockhand after any rollback succeeds.
